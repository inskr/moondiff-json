# 生态定位与边界

[moonbit-community/moondiff](https://mooncakes.io/docs/moonbit-community/moondiff) 已存在，主要比较
MoonBit 源码。MoonDiff JSON 面向 JSON 配置、API 响应和测试快照，不宣称生态首创；
没有运行跨库性能对比，不宣称速度优胜。

| 工具 / 策略 | 适用问题 | 边界 |
| --- | --- | --- |
| 普通文本 diff | 行、字符及格式变化 | JSON 格式和字段换序可能造成噪声；本项目忽略对象顺序，保留类型和精确数值语义 |
| 源码 moondiff | MoonBit 程序源码 | 输入领域不同；本项目没有源码分析功能，不依赖它 |
| position（默认） | 顺序有含义、没有稳定身份的数组 | 中间插入导致后续位置变化；没有 LCS 或模糊匹配 |
| 显式 array_rules / by_key | 含唯一字符串或整数身份的对象数组 | 缺失、重复、非法身份报错，不退回位置；身份改变产生新增和删除 |

身份数组默认忽略顺序，check_order 只比较共有身份的相对顺序。数字与字符串身份不同；
1 与 1.0 相同，相邻大整数不同。整块新增删除只报一次，双侧路径遵循 RFC 6901，根路径为空字符串。
忽略不能绕过严格解析、重复对象键和资源限制。

只支持严格 JSON、JS backend。默认单侧 2 MiB、100000 节点、深度 64（根为 0），最多 10000
变化；选项仅能收紧限额。超限返回完整错误，不截断。数字 token 最长 256，显式指数绝对值
≤10000；完整边界见 reports-and-options.md。不做 YAML、Patch、写回、LCS、云服务、登录或 LLM。

技术取舍：经实际验证的 moonjson 保留数字 token，再转为无 Double 的受控树；用符号、有效数字
和十进制指数规范化做精确相等，避免任意精度算术依赖。Map 身份索引代替两两扫描；固定码点排序
保证字节确定性，身份排序不承诺数值大小顺序。MoonBit 比较和报告，CLI/Worker 共用字符串入口；
网页每页显示 100 条、下载保留完整报告。首次载入后可离线比较，刷新离线与终止后离线重建不作 PWA 保证。
