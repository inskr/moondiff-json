# 比较语义（完成至任务 4）

本阶段提供 MoonBit `diff_documents(Document, Document, Options)` 核心接口。
选项 JSON 的严格解析及正式 analyze/report 字符串接口由任务 5 实现。
下文 JSON 选项展示最终配置语义，当前测试直接构造同等的 MoonBit Options。

## 通用比较

对象按解码后的 Unicode 码点顺序、深度优先比较；字段排版或换序不构成变化。
同类型容器递归，整体新增/删除只报告一次，类型变化只报告一次 modified。
null、缺失、数字和字符串分别处理。数字从原始 token 正规化后精确比较，
1、1.0、1e0 相等，相邻大整数保持不同；片段保留原始数字 token。
路径采用 RFC 6901，根为 ""，空字段名为 "/"，旧新路径独立记录。
默认数组按共享索引比较，再新增/删除尾部；中间插入可能引起多个 modified。
更多基础规则见 basic-comparison.md。

## 显式唯一键数组

例如对 /users 数组使用直接属性 id：

```json
{"array_rules":[{"path":"/users","key":"id","check_order":false}]}
```

不会自动猜测 id、name 等字段。规则路径只允许根数组或从根经对象成员到数组；
根数组路径为 ""。不能进入其他数组，不能在身份匹配的对象内部再配置数组规则。
空属性名可用作身份 key；Pointer token 解码后匹配，不按文本前缀匹配。
重复规则 path 始终报 INVALID_OPTIONS。

未被整体忽略的规则至少要在一侧定位到数组。另一侧缺失合法；存在非数组、
双方均缺失、路径进入其他数组均报 INVALID_OPTIONS。
对每侧先建立 Map 索引；全部元素必须为对象并含有 key，身份必须为字符串或精确数学整数。
1 与 1.0 属于同一身份，字符串 "1" 与整数 1 是不同身份；0 与 -0 是同一身份。
1.2e1 是整数身份，0.1 不是。布尔、null、数组和对象身份全部拒绝。
缺失、重复、非法身份返回 INVALID_ARRAY_KEY，不退回位置比较。
错误携带侧别、元素身份字段 Pointer，说明中包含数组路径及索引；没有解析位置时保留 null。

共有身份递归比较，旧、新索引分别生成路径；身份变化表现为删除旧元素和新增新元素。
元素及其后代的 identity 包含两侧数组路径、属性名和精确身份 JSON 字符串。
共有身份使用旧侧原始数字 token；新增元素使用新侧 token。字段的 before/after 分别保留各侧原文。
数组级 reordered 和整个数组的新增/删除不关联单个身份，identity 为 null。

## 顺序与确定性

check_order 默认为 false；纯换序不会产生变化。
启用后只比较两侧共有身份的相对顺序，最多产生一条 reordered，先于该数组的元素变化。
新增首项、删除首项、没有共有身份，都不会单独导致重排。
reordered 的 before/after 为对应侧共有身份序列，不包含只在一侧出现的身份。

元素变化按规范化身份键的 Unicode 码点顺序输出：

- 字符串：`S:` 后接解码内容；不做 Unicode 规范化。
- 整数：`N:<sign>:<digits>:<exponent>`，sign 为 `+` 或 `-`，其余来自 NumberKey。

这是确定性输出顺序，不是数学大小排序。例如 10 的键 N:+:1:1 会排在 2 的键 N:+:2:0 前。
不依赖 Map 迭代顺序，排序不展开巨大指数，也不使用浮点数。
相同输入/Options 得到相同结构、路径、身份和片段；完整 envelope 字节确定性仍须在任务 5 验证。

## 整块变化、忽略和限制

所有规则目标先做必要的数据验证，即使目标位于整体新增/删除的父对象内部。
一个数组整体新增/删除时，先验证已有侧全部身份，然后按通用规则只报告整个数组一次。

重叠忽略数组或其父对象时，依据规格跳过该规则的数据校验，包括目标存在性和身份检查；
重复规则仍拒绝，配置 JSON 的类型、Pointer 格式等检查由任务 5 负责。
输入 JSON 的严格解析、重复对象键、数字、字节、深度、节点上限检查先于忽略。
忽略不能绕过这些输入检查；它不是脱敏功能。

所有变化（包括 reordered）计入 max_changes。超限抛错，不返回部分成功报告。
比较只取一次每侧 Document 快照，不修改原文档或调用者的 Options。
